Constitutional ruling established reviewing the CC deposit-side KISS gate (`cc_ng_organism.py`, 2026-07-08, branch cc-laptop-deposit-kiss-20260708).

**Rule:** Keying a dedup / reinforce-on-recurrence decision on a signal the substrate itself produced — an embedding cosine-similarity hit, a fired-node `concept_label`, or provenance tags set at deposit time (`cc`, `creation_mode`) — is NOT a LAW-7 classification-before-ingestion violation. It is acceptable *structural* dedup. The prohibited thing is classifying/labeling the raw *incoming* experience before it enters the substrate.

**Why the distinction holds:** LAW 7 protects raw experience on its way IN. Emergent artifacts (e.g. `cc:want::` want-nodes generated by the Tonic) are DERIVED from substrate state that already ingested raw — deduping them on a substrate-derived key collapses nothing that wasn't already the substrate's own structural identity. The KISS redundancy gate never reads `content`; it matches on embedding similarity + structural tags only.

**How to apply:** When you see a gate/dedup at a deposit boundary, ask: does it read the raw content and assign a label BEFORE the substrate sees it? → LAW-7 violation. Or does it key on similarity/topology/provenance the substrate already produced? → compliant structural dedup.

**Watch-out (the `(unknown)`-bucket anti-pattern):** structural dedup keyed on a resolvable label must guard the *unresolvable* case. Collapsing all label-less items into one `"...::(unknown)"` node conflates distinct emergent states and overwrites their snapshot each recurrence — that IS a loss of the substrate's genuine distinct wants (ethos/Duck-Ethics regression), not mere noise reduction. Correct pattern: dedup only when the structural key resolves; fall back to distinct-per-item (or don't materialize) when it is unknown. See [[tid-peninsula-locked-form]] for the sibling "never store a form that discards a decision" principle.
