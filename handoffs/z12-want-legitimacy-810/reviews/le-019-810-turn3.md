If the nearest closer is far away or absent every call scans to it. Measured (scratch, this laptop, `parse_wants` only): `("https://x.org/a?[WANT]w " * N) + "[/WANT]"`: N=5,000 (120 KB) **0.41 s**, N=10,000 (240 KB) **1.23 s**, N=20,000 (480 KB) **4.29 s**, N=40,000 (960 KB) **16.3 s** (x~3.7 per doubling = quadratic). Add the adversarial shape to the bounded-cost test.

**F2 (MEDIUM, false negative, residual under-described): the JSON rule fires on ordinary English/numbers, not only "JSON-looking sentences".** build-003 section 1 Fix 3 says a REAL `true,`/`false,`/`null,` token "is the same accepted precision trade as a want typed inside `{"note": "..."}` ... **not a bug the token check can fix**". Both halves are inaccurate. Run on the final function (base mints every one; build drops both markers `in_json_string`):
- `It is true, "[WANT]revisit this[/WANT]", she said.` ; `That is false, "…"` ; `if null, "…", ok`  (the English words true/false/null)
- `In 2026, "[WANT]revisit the exit policy[/WANT]", I wrote.` ; `Chapter 3, "[WANT]revisit this[/WANT]"` ; `we saw 12, "…"` (any digit before `, "`)
- `-true, "…"` / `.null, "…"` (non-identifier char before the word)
Condition: word-or-digit, comma, opening quote, then the quote closed on the same line and followed by `, } ] :` or end of node. The want text is not touched; the context is ordinary prose (a want typed in quotes after a clause ending in `true,` or a year). The worker's own named-residual test (`tests/test_cc_want_legitimacy_810.py:1171`) pins only `ok: true, "…"`.
**It IS fixable at the source without a content-aware exemption:** require the `true/false/null/number` token to itself sit in a JSON VALUE position (the previous non-blank character before the token is `,` `:` `[` `{`, or start of node/line). I prototyped this by monkeypatching `_want_json_opens_literal` in a scratch process (no repo edit): the 4 English/number cases above then mint like base; `{"a": true, "[WANT]note[/WANT]"}`, `[true, "…"]`, `{"a": 1, "…"}`, `[1, 2, "…"]`, `[-1.5e3, "…"]`, `"a", "b [WANT]x[/WANT]"` and the YAML-ish `ok: true, "…"` are all still `in_json_string` (unchanged from turn 3). Severity MEDIUM because it is a lexical guess that drops a well-formed want typed in ordinary quoted prose, in the same class le-016 #2/#3 were raised for; visible + recoverable (INFO line, source node), but not documented as prose-reachable.
