## Consequences items 6-7 introduce (for the NORMAL look; behaviour changed on purpose)
1. **While the ~806 cohort exists, D24 on the laptop never drains and never steps.** That is the ruling. The daemon says so with one ERROR per cycle (~every 60 s, ~1,440/day) even when the tract is empty; that volume is the "every cycle, never silent" rule, not a bug. The first LIVE batch therefore cannot happen until Leg 2 wires the cohort (the hold stands by the doc's rule).
2. **A node that cannot bind wedges the drain loudly:** the cohort until Leg 2; a dual pass that fails after depositing nodes (covered by a test); a tree-less, window-less first turn after a restart (bound by the NEXT turn's prev->current link, so it wedges only if no later turn arrives by the hook door either).
3. **A pending consolidation that is later blocked by the guard is dropped, not re-armed** (per the brief); its owed idle steps never run. The pre-check makes this rare (it stops the deposit up front), but a node that becomes unbound between a batch and its pending run does it.
4. **Counter meaning drift:** `drain_consolidation_skipped_unbound_arrivals` now adds the whole unbound population on every blocked cycle (+~806 per cycle while the cohort exists); use `drain_consolidation_blocked_unbound` for "blocked cycles".
5. **Guard cost** (measured on a synthetic 16k-node graph with 806 unbound, real `_unbound_nodes`): median 12.6 ms, max 15.8 ms, under `_step_lock`, once per paced cycle plus once per phase 2. Negligible.
6. **Merge interaction between the two daemon branches (found by a trial merge, read-only `git merge-tree`, no worktree touched):** exactly ONE textual conflict in `scripts/cc-ng-daemon.py`, the changelog block at the top (both branches prepend an entry; keep both). The code regions, including the `_autosave_loop` both edit, auto-merge. **But the merged daemon makes 4 of the #874 drain-site tests fail whenever `CC_NG_BATCH_SIZE`/`CC_NG_IDLE_STEPS` are exported** (e.g. this shell, and the S4 laptop): the merged daemon runs PACED, the tests' fake NG has no `cc_topology_merge`, and the fail-closed pre-check skips the drain (the guard doing exactly what it should). With the two variables unset the merged daemon passes all 90 of the #874 tests and all 46 of mine. The fix is one line in the #874 test file's `daemon` fixture: `monkeypatch.setattr(d, 'DRAIN_PACING', None, raising=False)` (harmless on the #874 branch alone). I did NOT put it in the item-2 commit, to keep that commit to the one guard; whoever merges second should add it.
